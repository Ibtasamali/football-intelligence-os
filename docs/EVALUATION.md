# Evaluation Report — Football Intelligence OS

The product runs on **synthetic, football-realistic data** (hackathon requirement). Every number below is generated by the scripts in `backend/eval/`: the hallucination, cost and latency results on our synthetic demo match, pattern detection on held-out synthetic matches with known ground truth, and an *optional external validation* of the models against public open data (StatsBomb Open Data: World Cup 2022, Euro 2024; no Premier League data; not used or shipped by the product). Models are always scored on data they were **not** fitted or tuned on. Reproduce with:

```bash
cd backend
.venv/bin/python -m eval.calibrate        # real-data pattern thresholds
.venv/bin/python -m eval.tune_synthetic   # supervised thresholds (train seeds)
.venv/bin/python -m eval.select_synthetic # model selection (validation seeds)
.venv/bin/python -m eval.fit_models       # xG + goal-threat on real matches
.venv/bin/python -m eval.deterministic    # pattern detection (test seeds), generalisation, next action
.venv/bin/python -m eval.llm_eval         # hallucination, cost, latency, translation (uses Azure OpenAI)
.venv/bin/python -m eval.report
```

## 1. Hallucination control

**Setup.** 18 highest-significance moments of *Synthetic demo match — Azure City FC vs Thames Athletic*. For each moment three texts are produced and judged against the **same evidence package** the platform computed from event data:

- **naive**: a typical chatbot prompt ("explain this moment") given only the event, teams, minute and score.
- **grounded**: our evidence-grounded prompt, first draft, *before* fact verification.
- **pipeline**: the published insight after the verification loop and substitution.

Metrics: an independent judge prompt splits each text into atomic claims and labels each SUPPORTED / UNSUPPORTED / CONTRADICTED with respect to the evidence. Separately, a deterministic check counts numbers that cannot be traced to the evidence.

| Condition | Claims judged | Supported | Unsupported | Contradicted | Texts with ≥1 bad claim | Untraceable numbers |
|---|---|---|---|---|---|---|
| naive | 94 | 42.6% | 56.4% | 1.1% | 100.0% | 0.0% (58 numbers) |
| grounded | 156 | 89.1% | 10.9% | 0.0% | 66.7% | 1.1% (174 numbers) |
| pipeline | 144 | 88.9% | 10.4% | 0.7% | 66.7% | 0.0% (173 numbers) |

### Microsoft Foundry evaluators

The same texts scored with Microsoft's **azure-ai-evaluation** SDK (Groundedness against the evidence package and Relevance to the request, 1–5 scale), judged by our Azure OpenAI deployment in Microsoft Foundry:

| Condition | Groundedness (mean, 1–5) | Grounded ≥ 4 | Relevance (mean, 1–5) |
|---|---|---|---|
| naive | 4.67 | 94.4% | 5.0 |
| grounded | 4.78 | 100.0% | 4.28 |
| pipeline | 4.78 | 100.0% | 4.22 |

The Foundry groundedness score judges whole texts and is lenient with short, plausible answers (the naive prompt also scores high). Our claim-level checker above is the stricter test, so we report both: Foundry confirms grounded texts stay at 100% ≥ 4, and the claim-level audit shows where the remaining errors are.

**Reading the results.** Grounding the LLM in the evidence package is the big win: unsupported or contradicted claims fall roughly fourfold and untraceable numbers fall to zero. The verification loop guarantees numbers, event IDs, sources and prediction wording; it does not rewrite *interpretive* sentences (e.g. "this boosted Argentina's momentum"), which a strict judge marks unsupported. So grounded and pipeline score within noise of each other on that metric. A semantic claim-level checker is the next step on the roadmap.


*Unsupported* does not always mean false: a naive model may state true real-world facts about famous players or national teams. It does mean the claim is **not traceable to the match data**, so it can't be shown in the WHY? panel or verified, and that's the risk this architecture removes.

## 2. Tactical pattern detection

**Ground truth.** The synthetic generator is driven by a tactical script (press intensity, block height, flank bias, full-back push). The detectors never see the script. Scripted phases become labelled windows. Tolerance: detection may start 1 min before to 3 min after the scripted window.

**Protocol.** Hand-set thresholds (tuned on seed 11), plus supervised thresholds fitted on train seeds 0–29; per pattern the better one was chosen on **validation seeds 30–59**; results below are on **test seeds 100–129**.

| Pattern | Precision | Recall | Detections | Scripted windows | Median detection delay | Thresholds |
|---|---|---|---|---|---|---|
| Transition Vulnerability | 64% | 76% | 108 | 90 | 4.0 min | supervised |
| High Press | 43% | 78% | 112 | 60 | 3.0 min | hand-set |
| Flank Overload | 76% | 72% | 85 | 90 | 5.0 min | hand-set |
| Deep Block | 91% | 97% | 32 | 30 | 2.0 min | hand-set |
| **Micro average** | **63%** | **77%** | | | | |

Many high-press "false positives" fall in phases where a team presses fairly hard but below the script's ground-truth threshold (e.g. Thames chasing the game at press intensity 0.72), so the precision is conservative.

### Real matches: calibrated, not hand-tuned

Real football is noisier than the generator, so the real-data profile is **calibrated on 5066 team-windows from 32 real matches** (demo matches excluded). Each pattern fires only when its statistic is unusual (target ≈ 7% of windows).

| Pattern | Trigger rate on calibration corpus | Share of team-minutes active on held-out finals |
|---|---|---|
| High Press | 8% | 17% |
| Flank Overload | 7% | 8% |
| Deep Block | 8% | 12% |
| Transition Vulnerability | 7% | 8% |
| Midfield Superiority | 7% | 7% |

Held-out matches: FIFA World Cup 2022 Final — Argentina vs France, UEFA Euro 2024 Final — Spain vs England, FIFA World Cup 2022 Semi-final — Argentina vs Croatia. Active share is higher than the trigger rate because hysteresis keeps a pattern on for several minutes once started.

## 3. Expected goals (xG)

Logistic model on distance, visible goal angle and header, fitted on 521 real non-penalty shots and tested on 189 shots from 8 held-out matches.

| Model | Held-out Brier ↓ | Held-out log loss ↓ |
|---|---|---|
| Constant (base rate) | 0.0601 | – |
| Previous hand-set FIOS model | 0.0557 | – |
| **Fitted FIOS model** | **0.0498** | 0.2025 |
| StatsBomb xG (professional, many more features) | 0.0504 | 0.1939 |

Correlation with StatsBomb xG: r = 0.747. Caveat: only 12 goals in the test set, so the gap to StatsBomb is not statistically meaningful; the honest reading is *comparable on this sample*. For real matches the platform uses StatsBomb's own xG; the fitted model serves synthetic and future feeds without xG.

## 4. Goal-threat prediction ("team scores in the next 10 minutes")

Grouped 5-fold cross-validation by match over 5074 live samples (417 positives).

| Model | Brier ↓ | Log loss ↓ | AUC ↑ |
|---|---|---|---|
| Constant base rate | 0.07581 | 0.2866 | 0.5 |
| Fitted logistic (xg_10, shots_10) | 0.0757 | 0.2844 | 0.566 |

| Predicted bin | n | Mean predicted | Observed |
|---|---|---|---|
| 0.00–0.06 | 911 | 0.054 | 0.083 |
| 0.06–0.08 | 2174 | 0.071 | 0.057 |
| 0.08–0.10 | 1063 | 0.089 | 0.089 |
| 0.10–0.13 | 589 | 0.113 | 0.143 |
| 0.13–1.00 | 337 | 0.172 | 0.11 |

**Finding.** Our original hand-set goal-threat model was **over-confident** (it predicted ~38% where ~12% happened; Brier skill −0.23 on the same corpus). The evaluation caught this; the refit model is calibrated but the signal for 10-minute goal prediction from event data is weak (AUC 0.566). Tactical-pattern and momentum features added no predictive value in cross-validation, so they were dropped. The UI labels this as a low-resolution estimate rather than overselling it.

## 5. Next-action model

Markov transitions learned live within each match, predicting the next event type before it happens: top-1 accuracy **68%** vs **44%** for always predicting a pass (72,274 predictions over 32 real matches).

## 6. Cost and latency (Synthetic demo match — Azure City FC vs Thames Athletic, production pipeline)

| Metric | Value |
|---|---|
| Events processed | 2344 |
| Deep (LangGraph) analyses | 77 |
| Published insights | 53 |
| LLM calls / tokens (in + out) | 25 / 70,771 + 15,312 |
| Events handled with zero LLM tokens | 98.93% |
| LLM cost for the whole match | $0.053 (at $0.4/1M in, $1.6/1M out; verify current pricing) |
| Fast path latency per event (p50 / p95) | 2.61 ms / 3.63 ms |
| Deep path latency per analysed event (p50 / p95) | 0.0 s / 34.9 s (measured while replaying the whole match in ~3 min, so the Azure deployment was rate-limiting (429) and calls queued; an unthrottled single analysis takes ~3–6 s) |
| Verification | 49 insights passed first time · 4 self-corrections · 1 field substitutions |

### Cost per fan at scale

Insights and translations are computed once per match (and once per language) and shared by every viewer. The naive alternative, a per-fan assistant that calls the LLM for the same moments, scales linearly.

| Concurrent viewers | Shared FIOS cost per match | Naive per-fan design | Saving |
|---|---|---|---|
| 1 | $0.05 | $0.05 | – |
| 1,000 | $0.05 | $52.80 | 1,000× |
| 100,000 | $0.05 | $5,280.00 | 100,000× |
| 1,000,000 | $0.05 | $52,800.00 | 1,000,000× |

Fan questions add cost per question, reduced by the shared answer cache and the zero-token re-style path ("explain like I'm a beginner" reuses already-verified text).

## 7. Multilingual commentary

24 translations of verified insights into es, ar, hi. Each translation is re-verified: no number may be added or changed (decimals, percentages and years must survive; Arabic-Indic and Devanagari digits are normalised) and player names must stay intact. Failures retry once, then fall back to verified English.

Verified: **91.7%** · first try: **70.8%**.

## Limitations

- The LLM judge is a model too (same family as the generator); it is instructed to be strict and sees exactly the evidence, but it is not a human annotation. The deterministic untraceable-number check is independent of any model.
- Pattern ground truth exists only for synthetic matches; on real matches we report calibrated activation rates, plus qualitative agreement with the known story of the final (Argentina's left-flank dominance before both first-half goals).
- Test sets for xG (goals) and goal-threat (positives) are small; differences of a few thousandths in Brier score are noise.
- Cost uses list prices that change; latency depends on Azure quota (429 throttling adds seconds under bursts).
